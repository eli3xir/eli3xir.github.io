# 网站运行与测试

运行环境：Node.js 22+，本地预览可用 Python 3。目标为 GitHub Pages 静态托管。

## 命令

仓库根目录运行 `npm install`，再执行 `npm --prefix tools install` 安装博客生成依赖。

| 命令 | 验证范围 |
| --- | --- |
| `npm run build:blog` | 从 Markdown 重建 39 篇文章和列表；不递归删除博客目录 |
| `npm run build:lightmaps` | 将 manifest 中的原始 JPEG 字节打包，不改变图片、UV 或 HDR 倍率 |
| `npm test` | 节拍、路由、拒绝存储、采样、接入脚本重复运行 |
| `npm run validate` | 55 页入口、import map、本地文件、脚本类型/语法及正文保留 |
| `npm run test:browser` | 全量连续/直接访问、交互与降级行为；自动创建本地服务 |
| `npm run test:audio` | 实际 OfflineAudioContext 渲染完整配乐、音量与重叠提示音，检查峰值/削波 |
| `npm run test:loading` | 真实 HTTP 慢速分块传输、下载中往返导航、停滞连接取消 |
| `npm run test:lightmaps` | 资源包完整、缺失、索引损坏、单张图片损坏的实际浏览器恢复 |
| `npm run test:performance` | 七个入口及九个实验首屏/实际交互的 50 组帧间隔、长任务和离屏绘制；注明模拟限制 |
| `npm run test:first-interaction` | 新上下文中的首次滴色、键盘落点与真实击砖，不在交互时新增着色程序 |
| `npm run test:article-images` | 传输层文章十二张图的实际解码、顺序、尺寸、来源署名及两视口布局 |
| `npm run test:image-inspector` | 大图查看的键盘、鼠标、模拟触控、阅读位置恢复、加载竞争和降级 |

首次浏览器检查前执行 `npx playwright-core install chromium`。已安装的浏览器可通过环境变量 `BROWSER_EXECUTABLE` 指定。Windows 可以用 `BROWSER_ANGLE=d3d11`；报告实际渲染器。

手动预览：`python -m http.server 8765 --bind 127.0.0.1`，访问 `http://127.0.0.1:8765/`。绝对路径、模块与导航要求 HTTP 服务。

## 输出与诊断

检查输出在忽略目录 `tools/test-results/`；截图研究与临时脚本在 `temp-docs/`。稳定结果写入 [验证记录](../../wiki/verification.md)。`window.studio.diagnostics()` 提供当前画面调用、几何和纹理统计。`AUDIT_QUICK=1` 只测七个入口；完整验收不设置它。`AUDIT_SCREENSHOTS=0` 可只跑行为。

单个行为复查可用 `AUDIT_CASE` 指定场景名称的片段，例如 `reduced-motion experiment`。输出的 `scope` 明确区分完整、入口和单场景检查。

`compact scenes` 检查短屏、手机和平板的实际模型投影、文字间距、滚动与尺寸改变；`late audio activation` 包含真实 AudioContext 外部暂停与手势恢复，核对时钟冻结、按钮状态及持续音轨身份。`HDR room maps` 核对全部 122 张光照图的实际尺寸、UV 通道与亮度倍率。手机尺寸模拟仍需真实设备补充验收。

`npm run test:reading` 检查两种视口的真实文章翻阅：按钮/键盘与模型命中、空白区域、连点连续性、暂停时钟、减少动态效果、45 次翻阅的纹理数量、原文进入与跨板块返回。输出 `tools/test-results/reading-audit.json` 及初始/翻页中截图；可设置 `BASE_URL` 检查部署版本。

`npm run test:signal` 检查项目工作台的发送端选择、键盘与实体命中、发送/到达内容、暂停声音、40 次发送的纹理稳定、减少动态效果、跨板块返回和无 WebGL 降级，验证实现笔记锚点与原项目保留。报告 `signal-audit.json` 包含实际 base；`signal-flow-*` 与 `signal-done-*` 截图记录传输和到达画面。支持 `BASE_URL` 与代理参数。

`npm run test:radio` 检查唱片命中、键盘播放、暂停与抬针、四声部静音及实际 master PCM、音轨/分析节点身份、跨页订阅释放、浏览器暂停恢复、减少动态效果、刷新偏好及无 WebGL 操作。`radio-audit.json` 记录真实 base 和采样峰值；手机视口同时模拟缺少 `cancelAndHoldAtTime` 的环境，开关只依赖通用的渐变增益 API。

电台专项还核对音波发射坐标系的四个参考点，覆盖桌面、手机以及切换到平板/短屏后滚动；检查静音、音量为零、暂停和减少动态效果下的发射状态，并确认跨页保持同一份粒子几何。画面复核仍需查看实际喇叭口音波，矩阵检查不能代替艺术判断。

`npm run test:potion` 检查实际暂停音频后的瓶塞返回、键盘/玻璃命中、空白区域、连点姿态与单次续接、半拍提示音、系统中断、减少动态效果、离开时取消队列，以及无 WebGL 的九实验入口。`potion-audit.json` 和 `potion-lift-*` / `potion-idle-*` 截图记录两种视口；新增按钮后的短屏/平板构图可用 `AUDIT_CASE='compact scenes'` 单独复核。支持 `BASE_URL` 检查发布版本。

药瓶专项还从 GPU 的实际透射纹理采样空背景，避免仅检查材质参数而漏掉阴影之后的白底问题。首次显现上传气泡几何后，连续 30 次反应应保持纹理/几何数量及对象身份；离开时液体与气泡的几何/材质各释放一次。暂停和减少动态时同步检查气泡状态与液面扰动，画面仍需人工复核。

`npm run test:skin` 检查实时房间配色：键盘与实体色样命中、空白区域、两组按钮同步、颜色途中改向、暂停/半拍/系统中断、减少动态、刷新和返回首页。实际核对副本共享几何/光照而材质独立，离开时仅释放独占材质，四次往返的 GPU 数量稳定。另阻塞首次模型响应后进入首页，确认同一请求的就绪状态正确回传；模拟一次 503 后重试，并覆盖存储失败、无 WebGL、320 短屏、768 平板与 844 横屏。`skin-audit.json` 记录实际 base；支持线上复查。截图只代表电脑上的视口模拟。

`npm run test:about` 检查键盘/棋盘命中、空白区域、途中改选、真实音频暂停与中断、半拍起步、减少动态、原文与联系入口。通过实际编译的水面 shader 检查波纹位置和强度；以手与棋子的世界坐标核对接触。连续 24 次动作应保持 GPU 几何/纹理，离开时水面几何/材质、瓷砖纹理、棋盘实例各释放一次，共享角色旋转与光环恢复。320、390、768、844 宽度各按三种活动的 41 个进度采样动作范围与锚点位置；包含无 WebGL。输出 `about-audit.json` 及活动/布局截图，支持 `BASE_URL`。等待正文平滑滚动实际到达后再验收，不将四元数的正负零当成姿态跳变。

关于专项还实际点击跑道与水面，覆盖全部三个物件入口；三种活动之间九种有序改选检查位置连续和手臂缩放，防止离开棋盘时继续跟踪棋子。程序状态检查之外，保存连续操作录像复核动作衔接和手机滚动。

`npm run test:character` 在真实角色闭眼期间暂停配乐及挂起 AudioContext，检查音频时间冻结时眼睛连续睁开，之后仍会自然眨眼；暂停下完成一圈活动，减少动态时眼睛稳定。关于进入实验室后保持共享角色、同一组音源与节拍，并再次核对暂停时睁眼。两种视口输出 `character-audit.json`、帧采样和暂停截图，支持 `BASE_URL` 线上复查；帧采样是表情状态证据，不是主观声音试听。

`npm run test:ocean` 检查首屏风力的键盘/船身命中、空白区域、改向连续、暂停/半拍/系统中断；通过浮点渲染目标比较 GPU 波高/斜率和 CPU 取样。驾驶区核对风力交接、W/S、键盘按钮、长按及取消、多点触控模拟、离屏停止帧增长；资源检查包含自定义帆影材质。另覆盖四种紧凑尺寸的波动范围、减少动态的显式开始和无 WebGL。输出 `ocean-audit.json` 与截图，支持线上 `BASE_URL`。所有手机尺寸和触控输入均为电脑模拟。

`room focus carries` 检查同一角色与相机的连续物件探索，包括途中改选、启用配乐、系统暂停音频和减少动态效果。`portal follows` 同时核对角色发光点、粒子、纸幕圆心与揭示结束的姿态连续性。

`room stays hidden` 暂缓光照图响应，核对模型不提前显现；随后释放请求并检查房间就绪，再模拟单张光照图失败，确认仍可进入房间。

正常加载时光照 JPEG 由一个 `lightmaps.bin` 请求提供；`model.lightmapSource` 记录包内成功数量与独立原图回退数量。包构建与校验入口为 `tools/pack-room-lightmaps.mjs`，修改光照图后先重建再运行 `validate`。包内图片经 Blob URL 解码，不能再从 `image.src` 推导原文件名；使用 `texture.userData.lightmapFile` 与 manifest 对应。

`test:audio` 同时检查 32 kHz 与 24 kHz、默认和最大音量。报告合成时间、PCM 字节数、整体/乐章 RMS 与峰值；信号通过不能替代音乐听感评审，也不能用桌面合成时间推断真实手机性能。

浏览器报告记录实际请求失败；首屏检查不会触发所有正文懒加载图片，不能据此声称外部图床全部有效。传输层旧 CDN 图及六篇中 65 处 Gitee 图已恢复；两张未确认的 MTCNN 原图仍待追溯。PNG 截图和帧间隔不能自动决定艺术效果是否合格。

`npm run test:breakout` 检查两视口的实际碰撞、暂停状态精确交接、四次快速往返、部分可见时控制转发、键盘、实体球场与模拟触控取消；核对离屏停止、角色握柄、重复三十局的资源身份和十三项释放事件。独立 GPU 目标检查移除砖块后的真实像素差；另核对有声半拍发球、音频中断后仍能击砖、四种紧凑尺寸全挡板范围与实际网格投影、四种桌面尺寸的标题和声音栏间距、减少动态及无 WebGL 游戏。输出 `breakout-audit.json` 和过程/降级截图，支持 `BASE_URL`。进入 iframe 后等待滚动稳定，键盘操作前明确聚焦画布，避免把输入留在父页。`npm test` 覆盖面/圆角/高速碰撞、漏接/过关、30/120 Hz 一致性、快照与不同和声的提示音；`test:audio` 另将五行击砖、接球和漏接声按 65 毫秒间隔叠加配乐，检查 24/32 kHz 与两档音量的有限性和削波。没有 WebGL 仍保留同一套游戏规则；录像及模拟触控不能替代真机或主观试听。
`npm run test:bullet` 检查两视口的完整弹幕精确交接、暂停、四次快速往返、控制转发、离屏停止和键盘避让；手机尺寸用 CDP 检查相对触控按下不传送、移动与取消，失焦清理按键。24 次重开与三种弹型检查 CPU 池、实例属性、几何身份和 GPU 数量，离开时十项独占资源事件各一次并恢复下一章背景/地面。独立 GPU 目标读取两颗单独弹丸的差分像素重心，与场地投影比较；另覆盖实体开始、半拍、音频挂起后实际擦弹、四种紧凑尺寸全玩家范围和弹丸边界、四种桌面声音栏间距、减少动态和无 WebGL。输出 `bullet-audit.json` 及场地/降级截图，支持 `BASE_URL`。`npm test` 检查相对线段穿越、擦弹一次、保护/结束/重开、三种发射频率、十秒换型与 30/120 Hz 一致性；`test:audio` 包含擦弹/受击密集叠加。该像素检查证明位置公式，不能代替艺术、抗锯齿、真实手机性能或音乐试听。

`test:performance` 顺序检查两种视口，每种含七个入口、九个实验首屏与九个下方实验，共 50 组。公开按钮或指针事件推动真实模拟，每组至少 2.4 秒/120 个 rAF 间隔（慢设备最多 12 秒），记录前后状态、资源、帧计数、程序数、长任务与大于 25/50 ms 的间隔。主入口使用静音环境；实验包含反复滴色、打散、转动、透镜移动和驾驶。`PERF_CASE=fluid` 或 `breakout` 可定向检查一项的两种视口，`BASE_URL` 可指向部署站点。测试时不要并行运行其他 GPU 审计。此脚本不测完整音乐负载、加载速度、GPU 定时或真实手机。

`test:first-interaction` 使用独立新上下文测试流体与打砖块各两种视口，从按钮触发前开始采样，并验证实际模拟推进、真实击砖和首次操作前后程序数量稳定。最长间隔只作测量记录，不用依赖电脑速度的绝对阈值作正确性断言；输出 `first-interaction-audit.json` 与截图。支持 `BASE_URL` 线上核验，初始化预热本身不包含在运行帧间隔中。

`test:article-images` 在两种视口中依次滚动并解码传输层文章的十二张本地图，核对清单中的原 alt、尺寸、顺序与可见性，以及出处链接、无溢出和无失败请求；支持 `BASE_URL`。`validate` 同时检查图片 SHA-256，并仅在该篇正文比对中把清单中的十二个本地地址还原为旧地址。`build:blog` 读取可选 `source_url`/`source_name` 元数据生成正文之后的出处说明，其他文章结构不变。恢复依据和无法进行旧 CDN 字节比对的限制见公开参考。

`npm run test:quality` 用真实设置控件检查八个 WebGL 实验、两种视口，每项循环三次低/高/自动，核对主/子像素比、画布缓冲尺寸、阴影、渲染器与模型身份及程序/几何/纹理稳定。先实际发球、开始弹幕、滴色、曝光、换字、驾驶或着陆，再验证暂停快照相同或活动进度连续。额外覆盖刷新、真实第二标签的存储事件、删除、非法值、宽窄视口变化、存储 getter 拒绝、减少动态的延迟启动、跨路由、错误消息、无 WebGL 流体和玻璃实时 DOM。`QUALITY_CASE=fluid` 可定向一项，`QUALITY_SPECIAL_ONLY=1` 只跑四组边界情形；输出 `quality-audit.json` 及月面/流体/打砖块两档截图，支持 `BASE_URL`。

`test:first-interaction` 另支持 `QUALITY_MODE=low` 或 `high`，通过真实设置控件在进入实验前选择档位，继续验证首次滴色及击砖的着色程序稳定。报告记录档位，避免把省电测量误写成默认画质结果。两类测试仍在桌面浏览器模拟尺寸与 DPR，不能替代真机性能或艺术验收。

`npm run test:article-reading` 检查 39 篇文章在两种视口中的标题、实际几何与文案避让、章节锚点和目录；四种额外尺寸逐姿态核对完整翻页。两种视口验证纸角抓握、肩掌连接、掌大小、最终重新抓握连续性、键盘翻页、目录焦点、书签同步、离屏暂停、纹理稳定、减少动态和单标题公式；另覆盖无 WebGL 阅读。延迟放行十二张传输层配图后比较各章节绝对位置，核对直接深链接仍正确，并让浏览器解码全部 70 张本地图对比构建宽高。支持 `BASE_URL` 及 `ARTICLE_INTERACTION_ONLY=1` 跳过 78 个初始构图检查；报告 `article-reading-audit.json`。`test:reading` 继续检查文章列表、连续输入和节拍同步。图床外链没有本地元数据，不能把本地图结果扩展成全部外链可用。

修改文章后使用 Node 22 运行 `build:blog`，再运行 `validate`。构建期 `image-dimensions.js` 按源文件内容读取 PNG、JPEG 和当前简单有损 WebP，不联网猜测尺寸；不支持的本地文件使构建失败。原文比对只移除已经核实的尺寸属性，并按 `article-formatting.json` 逐项还原强调格式；不要用一般化 HTML 清洗跳过内容保护。

深链接场景还延迟首轮主样式请求，确认阅读布局在定位前已确定。阅读规则统一保存在 `experience.css` 尾部；不要恢复成定位后才追加的独立样式，否则冷缓存访问可能停在上一节。

`npm run test:recovered-images` 检查六篇中的 65 处恢复配图：两种视口逐张原生解码、滚动到正文、核对 alt/位置/比例/溢出与出处，并延迟 26 张数据链路层图验证章节定位，另延迟正文网页字体检查视口内阅读位置，共十六组。支持 `BASE_URL`，`RECOVERED_LAYOUT_ONLY=1` 只运行四组图片/字体布局检查；输出 `recovered-images-audit.json` 和每篇首末图及出处截图。两张未确认原图使用显式 404 模拟检查失败提示，不算恢复成功。真实旧地址的 404 已另外实际请求核实，来源及 SHA-256 保存在 `assets/blog/recovered/manifest.json`。

当前 `test:article-reading` 的独立解码覆盖已从上述第三十轮的 70 处扩为 135 处本地图。`validate` 还校验恢复文件的 SHA-256、尺寸与字节数，按文章内序号单独还原每一个原链接；同一图的重复位置不得用全局替换归并。

图片延迟测试先等待 `document.fonts.ready`，再比较章节绝对位置，确保只测图片占位变化；独立字体测试显式扣住 SpaceGrotesk 请求，验证替换字体之后目标仍在视口顶部约 62 px、焦点与书页索引保留。字体使标题换行、章节文档坐标改变时，浏览器可同时补偿滚动位置，不能仅凭文档坐标变化判断读者丢失位置；要记录目标视口坐标与 scrollY。

`npm run test:image-inspector` 共七组，覆盖桌面和窄屏的实际放大、整图边界、原生像素、鼠标拖动、方向键、Tab 双向循环、背景不可聚焦、Escape 返回、八次重复打开、尺寸改变和打开中切页；另检查带触控的移动模拟、加载中关闭、源图 404、无 WebGL/减少动态以及不支持 showModal 的原图新页。触控通过 Chromium CDP 分别沿两轴发送可信事件，包含取消；原生轴锁会限制单次斜拖，不能要求斜拖必然同时移动两轴。输出 `image-inspector-audit.json` 及整图/细节截图，支持 `BASE_URL`；模拟不替代真机手势和辅助技术评审。

全部文章构图检查还核对每处本地图都有语义放大入口及至少 44×44 px 的目标。章节全量扫描仅对清单内两张未恢复原图显式回复 404，并在报告记录 `simulatedUnavailable`；其余任何失败仍中止检查。它沿用配图恢复专项的确定性失败场景，不把外网连接异常忽略为成功，也不把模拟结果称为源站恢复。

字体检查的最终视口位置距 62 px 与前后位移均采用不超过 2 CSS px 的容差；图片加载导致的章节文档位置比较仍保持 1 px 容差。第三十二轮实际复现了字体替换后的 1.3125 px 残余位移，原始数值与失败过程见验证记录，不将其报告为零偏差。

`IMAGE_INSPECTOR_FALLBACK_ONLY=1` 可只复查原图新页降级；报告额外保留此组页面错误和请求失败，便于区分进入场景前的超时与查看器行为。线上检查若分次完成，应记录实际组合范围和最初失败，不将定向通过写成一次完整七组通过。

延迟图片场景还记录字体完成后的 `anchorBefore` 与 `anchorAfter`，要求图片引起的视口位移小于 1 px；两者距预期 62 px 的范围允许前述 2 px 字体残余。此处不能因加载前已有字体偏差而把零图片位移判为新图片定位错误。
